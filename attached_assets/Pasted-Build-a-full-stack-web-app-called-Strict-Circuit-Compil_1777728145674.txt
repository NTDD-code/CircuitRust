Build a full-stack web app called "Strict Circuit Compiler" — a Rust-inspired
circuit design tool where users describe electronic circuits in a strict custom
syntax. The system compiles, validates, and exports them with AI assistance.
The app is built for the Vibe Code competition. UI must feel like a real
professional IDE — dark, fast, and impressive.

## CORE CONCEPT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The user writes circuit code in a custom Rust-inspired DSL.
The compiler enforces STRICT rules — any wiring/logic error immediately
throws a hard compile error (with code + line number). The circuit CANNOT
be exported until ALL errors are resolved. Zero tolerance — exactly like
the Rust compiler. No warnings. Only errors or success.

### 1C — Backend Proxy Routes (Node.js/Express)

The frontend must NEVER call Ollama or Anthropic directly from the browser
(CORS issues). All AI calls go through the Express backend:

  POST /api/ai/chat
  Body: {
    provider: "cloud" | "local",
    model: string,
    systemPrompt: string,
    userMessage: string,
    ollamaUrl?: string   // only if provider = "local"
  }

  Backend logic:
  - If provider = "cloud":
      → Call Anthropic API using ANTHROPIC_API_KEY from env
      → Model: body.model
      → Return: { response: string, provider: "cloud", model: string }

  - If provider = "local":
      → Call POST {ollamaUrl}/api/generate
         Body: { model, prompt, stream: false, system: systemPrompt }
      → Return: { response: string, provider: "local", model: string }

  POST /api/ollama/models
  Body: { baseUrl: string }
  → Call GET {baseUrl}/api/tags
  → Return: { models: [{ name, size, modified }] }
  (This proxy avoids CORS when calling Ollama from the browser)

  POST /api/ollama/pull  ← BONUS FEATURE (see Feature 1D)
  POST /api/ollama/status
  → Check if Ollama is reachable → return { alive: boolean }

## FEATURE 3 — STRICT VALIDATION ENGINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Implement a parser + validator that processes the DSL. On compile:
1. Parse all declarations → build component graph
2. Parse all connect! statements → build net/node adjacency map
3. Run all rules below in order

Hard error table — any match = BLOCK EXPORT:

  E001 | Undeclared component used in connect!
       | "connect!(Q99.base → ...)" but Q99 was never declared
  E002 | Net connected to itself
       | "connect!(sig → sig)" — short circuit
  E003 | VCC connected directly to GND
       | "connect!(vcc → gnd)" — catastrophic short
  E004 | Output pin connected to another output pin
       | Two collectors joined without load — conflict
  E005 | Input pin declared but never connected (floating input)
       | A base pin that is never driven
  E006 | Component declared but never used in any connect!
  E007 | LED connected without a series current-limiting resistor
       | Trace the net path: if LED anode → net → VCC with no resistor
         in the path → E007
  E008 | High-current component (Motor, Buzzer, Solenoid, Relay)
       | driven directly from MCU GPIO pin (ESP32, Arduino, STM32)
       | without a transistor or MOSFET in between → E008
  E009 | Voltage mismatch on a net
       | Net::VCC{voltage:5.0} connected to a pin with max_voltage:3.3
  E010 | Duplicate component identifier
       | Two "let R1 = ..." declarations
  E011 | Pin used more than its allowed connection count
       | e.g. a GPIO pin connected to 5 outputs simultaneously
  E012 | Missing pull-up/pull-down on open-collector output
       | Open-collector pin with no resistor to VCC or GND
  E013 | Capacitor polarity reversed
       | Electrolytic cap: positive pin connected to lower potential net

Each error output format (exact string):
  error[E007]: LED 'D1' has no current-limiting resistor in series.
               Connecting LED directly to VCC will destroy it.
               → Line 18, Net: vcc_rail
               fix: add a resistor between VCC and D1.anode

Show all errors at once (like Rust — don't stop at first error).
After fixing ALL errors: emit success message, unlock export buttons.

## DSL SYNTAX — PARSER SPEC
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Implement a parser for exactly this syntax:

circuit IRObstacleSensor {

  // ── Components ──────────────────────────────────────────
  let Q1  = Component::Transistor { model: "2N2222", package: "TO-92",
                                    max_ic: 0.6, max_vce: 40.0 };
  let R1  = Component::Resistor   { value: "10k",   tolerance: "5%" };
  let R2  = Component::Resistor   { value: "1k",    tolerance: "5%" };
  let D1  = Component::LED        { color: "IR",    vf: 1.2, max_if: 0.05 };
  let D2  = Component::LED        { color: "red",   vf: 2.0, max_if: 0.02 };
  let BZ1 = Component::Buzzer     { voltage: 5.0,   current: 0.03 };

  // ── Nets ─────────────────────────────────────────────────
  let vcc = Net::VCC    { voltage: 5.0 };
  let gnd = Net::GND;
  let sig = Net::Signal { name: "trigger" };

  // ── Connections ───────────────────────────────────────────
  connect!(vcc    -> R1.pin1);           // VCC to resistor
  connect!(R1.pin2 -> D1.anode);         // Resistor to IR LED anode
  connect!(D1.cathode -> gnd);           // IR LED to GND
  connect!(sig    -> R2.pin1);           // Signal to base resistor
  connect!(R2.pin2 -> Q1.base);          // Base resistor to transistor
  connect!(vcc    -> BZ1.vcc);           // Buzzer power
  connect!(Q1.collector -> BZ1.gnd_pin); // Transistor switches buzzer
  connect!(Q1.emitter   -> gnd);         // Emitter to GND
  connect!(vcc    -> R3.pin1);           // Indicator LED series R (E007 safe)
  connect!(R3.pin2 -> D2.anode);
  connect!(D2.cathode   -> gnd);
}

Parser must:
  - Tokenize by line → track line numbers for error reporting
  - Build a ComponentMap: id → { type, model, pins, metadata }
  - Build a NetMap: netName → { type, voltage?, connections: [pin refs] }
  - Build an AdjacencyList for the electrical graph
  - Export internal AST as JSON for AI safety analysis + KiCad export
